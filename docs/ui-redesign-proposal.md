# Zxtract 界面重设计方案

状态：设计提案，尚未改动应用实现。

## 目标与问题

将产品定位为轻量、可靠的 Windows 解压工作台。用户首先看到待处理文件和下一步操作，复杂设置按需出现。

当前界面的主要问题不是控件大小，而是层级混杂：模式切换、密码配置、左侧来源与输出表单、统计条、任务表同时争夺注意力。虽然信息有所压缩，用户仍须在多个区域寻找操作。两种模式共用列表，也缺少明确的任务作用范围。

| --- | --- | --- |

## 推荐架构：单栏任务工作台

取消固定的左侧配置栏和独立统计面板。界面从上到下只有五个层级：

1. 固定工具栏：文件解压 / 文件夹解压页签、添加来源、主要执行按钮、更多菜单。
2. 条件性来源行：只有文件夹模式显示根目录、选择目录、包含子目录说明与扫描入口。
3. 通用设置条：本次密码、输出位置、更多选项。两种模式共享入口，标题明确作用于下一次启动的任务。
4. 主任务列表：占据剩余空间，列表内只显示当前模式的任务。
5. 底部状态栏：一句进度或完成摘要，以及日志入口。

工具栏、来源行和设置条固定；只有任务列表滚动。切换页签保留各自的任务和来源，不清空、自动扫描或自动启动任务。

## 操作与状态

- 空列表：中央只放“拖入压缩文件”和“选择文件”按钮；文件夹模式显示对应的目录选择提示。
- 文件模式：添加文件后启用“开始解压”。支持多选文件，普通解压默认不递归。
- 文件夹模式：选择目录后启用“扫描并解压”；“仅扫描”作为次要文字按钮。模式名称避免含糊的“自动”，递归开关有简短说明。
- 运行中：开始按钮所在区域显示当前执行控制。暂停仅在实际支持暂停的流程中显示；取消在运行时出现。
- 切换到另一个模式时若后台仍有任务运行，显示“文件夹解压正在运行”及返回入口，运行控制明确标识作用对象。
- 完成后：底部显示成功、失败与取消的数量；有异常时提供“查看需处理任务”。不新增仪表盘卡片。

## 密码与输出

通用设置条默认以简短文字显示当前设置，不常驻大输入框。点击“密码”打开紧邻设置条的编辑面板：多行候选输入、路径推断开关、从密码库选择。面板可保留展开状态，频繁输入者无需重复点击。

密码库与推断规则仍在独立管理窗口。密码库增加用户可命名的标签，例如“课程资料”；默认掩码旁展示标签，解决多个同长度掩码无法区分的问题。明文查看必须由用户主动触发，关闭面板后恢复隐藏。密码仅显式保存。

输出位置采用三个清楚的中文选项：压缩包所在目录、同名子文件夹、指定目录。选择指定目录才出现路径选择；取消重复的“使用自定义输出目录”勾选项。

“更多选项”包含冲突处理、并行数、成功后删除源文件。文件夹特有的分卷归并、递归上限只出现在文件夹模式的选项中。

参数在启动或重试时形成快照。运行中的任务不受后续编辑影响；重试保留原输出路径，密码问题可单独覆盖。切换模式不会改变正在执行的任务参数。

## 任务列表与失败恢复

主列表保留文件、状态 / 进度、操作三类信息。次级路径用较浅文字显示于文件名下。完整路径可复制，分卷数量作为文件信息展示。类型、阶段、轮次、完整输出目录和底层错误放在选中任务的详情面板。

状态全部使用中文，并映射到下一步操作：

| 状态 | 直接操作 |
| --- | --- |
| 密码不匹配 | 修改密码并重试 |
| 已取消 | 重试 |
| 缺少分卷 | 查看分卷及缺失情况 |
| 已完成 | 打开输出位置 |
| 其他失败 | 查看原因、重试 |

多选后显示批量重试与移出列表。移出任务不删除源文件。普通文件与跨目录分卷任务的重试均应复用原任务上下文，不能丢失分卷集合。尚不能可靠归类的错误显示“解压失败”，保留原错误说明，不推测原因。

## 视觉方向

采用有分寸的 Windows 桌面工具风格：白色列表、浅中性灰背景、墨色文字、一个低饱和蓝色强调色。主要执行按钮和当前页签使用强调色；异常状态用少量红色或琥珀色，同时显示文字。

- 不设置宣传大标题、渐变背景、装饰性插画或独立统计卡片。
- 以细分隔线和对齐建立层级，避免每个区域都套圆角容器。
- 圆角统一为约 4–6 DIP，正文约 13–14 DIP，行高约 48–56 DIP；标题最多一个层级，不放大字号堆叠。
- 使用统一线性图标和明确文字，不用 emoji 做功能图标。
- 文案使用“添加文件”“开始解压”“修改密码”“打开位置”，避免“智能助手”“一键赋能”等宣传措辞。
- 仅在真正处理时显示进度；总进度不能计算时显示正在处理的文件数，不显示虚假的完成百分比。
- 兼顾键盘焦点、屏幕阅读器、Windows 缩放和长路径；重要入口不能依赖悬停才出现。
- 小窗口保留模式、来源、密码和开始按钮；次要命令收进更多菜单。目标适配 1024×640 起及 125% / 150% 缩放，按实际布局验证，不只适配默认大窗口。

## 实施顺序与验收

第一阶段做界面原型：空列表、处理中、有失败任务、小窗口四种状态，先确定骨架和视觉比例。

第二阶段迁移现有功能：固定导航、模式任务筛选、通用编辑面板、紧凑任务列表、日志入口。保留现有解压服务。

第三阶段补齐流程能力：中文状态映射、任务参数快照、分卷任务重试、可命名密码库、批量操作。这些是业务行为变化，需要对应验证，不能当成纯样式修改。

验收重点：首次使用能立即找到文件入口；滚动时模式页签始终可见；修改密码后可从失败任务直接重试；常用操作不用横向滚动；两种模式切换不丢任务；默认界面不需要滚动寻找开始按钮。
