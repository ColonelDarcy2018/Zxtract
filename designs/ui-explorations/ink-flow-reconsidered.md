# 墨流：统一状态工作台

本轮交付为可交互设计方案，未修改现用 WPF 界面、可执行文件或业务状态。前一轮已验证的应用仍保持原样。

## 设计判断

原来的底部批次条把列表状态重新编码成颜色分段，却没有带来新的操作或明确问题答案，用户还需要学习图例，因此删除。新的界面只保留一个全局状态中心；每行状态保留，它负责定位具体任务。筛选不是第三份状态报告，而是操作入口。

全宽任务列表替代常驻右侧详情。每行前面的箭头按需展开来源、输出位置与路径操作。常用的打开位置、修改密码仍留在对应行；低频操作通过行尾菜单呈现。

## 布局

- 标题栏：Zxtract 标识、保留拖拽空白、设置齿轮、最小化/最大化/关闭。设置齿轮紧邻最小化左侧，带提示和键盘入口。
- 展示区：模式、标题、当前目录、主操作和唯一会话状态。右侧扩大水墨画面，左侧保留干净的文字底。常规高度约 260px，矮窗口收至约 210px；不以持续占用列表空间换取图片面积。
- 本次参数：密码、输出位置、解压选项。与任务有关的选项不藏入全局设置。
- 文件列表：统一列起点，常规行高约 64px。状态主要用文字与少量颜色，保留当前文件与单包百分比，不再增加每行一条重复进度线。
- 窄页脚：日志与导出入口，无第二个全局状态区；展开日志后以日志自己的操作栏替代页脚，避免重复入口。

皮肤、轻柔动效、密码库与推断规则、版本说明归入设置。没有虚构自动更新、实时速率、剩余时间、下载功能等现有应用不具备的能力。

## 状态语义

| 会话阶段 | 表现 | 含义 |
| --- | --- | --- |
| 准备 | 中性状态说明与主操作 | 确认目录、密码和输出后启动；文件夹模式保留仅扫描。 |
| 扫描 | 流动的不确定条 | 文件数是已检查数量，不伪造百分比。 |
| 解压 | 约 12px 的确定进度条 | 明确标为已结束 X/N 个任务，包含成功、失败和取消；不代表整体字节进度。分卷集合算一个任务。 |
| 暂停调度 | 同一位置的暂停说明与冷色进度 | 不启动新任务，已启动任务继续；正式实现仍随真实完成事件更新比例。 |
| 完成 | 同一条转为完成色，停止动效 | 成功结束并保留各行打开位置入口。 |
| 有任务需处理 | 橙色结束结果与查看需处理 | 单项失败不会在运行期间把整个会话标成失败；仅会话结束后呈现此结果。 |
| 取消 | 中性结果说明，无成功满格条 | 保留成功结果，未完成项仍可在列表中定位。 |

候选密码的修改不会误表示已经改变正在进行的会话。当前应用不支持在忙碌时重试，设计稿也禁用这一情境动作；会话结束后的修改密码与重试可体验。

## 动效

背景只在进入运行阶段时做一次很轻的变化，之后静止。进度条做短暂进入反馈并平滑更新；只有扫描这种进度未知的阶段保留循环提示。暂停、完成、取消不持续闪动。设置里可关动效，也响应系统减少动画偏好；无动画时保留完整文本与状态语义。

## 设计依据

- [Windows 标题栏](https://learn.microsoft.com/en-us/windows/apps/develop/title-bar?tabs=winui3)：设置入口与拖拽区分离，保留系统窗口按钮及缩放后的可操作性。WPF 落地应通过 WindowChrome 等受支持机制保留窗口行为，不只复制四个图标。
- [Windows 进度控件](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/progress-controls)：确定与不确定进度分别对应可计量和未知完成量的操作。条的厚度、色彩及放置位置是本项目的设计决定。
- [Windows InfoBar](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/infobar)：信息需要有实际注意或行动价值，并避免频繁闪现、布局跳变。
- [Fluent 2 动效](https://fluent2.microsoft.design/motion)：自然、短促、围绕任务，并允许关闭。

## 审阅与验证

交互稿使用示例任务，不启动系统窗口操作，不修改真实剪贴板、密码库或压缩包。可体验设置、两种皮肤、任务展开、行菜单、筛选/搜索、暂停/恢复、密码重试、取消确认和版本说明。

已检查 1400、1024、736、320px 宽度，不存在横向控件溢出；补查了 320px 下的设置、选项、密码、详情和版本说明。检查了所有七种状态及关闭动效、系统减少动画偏好；脚本没有运行错误。抽查列表、菜单、参数面板和页脚中启用文字与所在纯色底的对比度，深色最低 7.21:1、浅色最低 5.04:1；这不是对背景图、透明度和所有悬停状态的完整无障碍审计。

图稿为审阅展开全部示例任务，不能把它当作 WPF 1024×640 的真实运行截图。正式实现必须在固定窗口中滚动并虚拟化列表，并在矮窗口压缩顶部展示区。
